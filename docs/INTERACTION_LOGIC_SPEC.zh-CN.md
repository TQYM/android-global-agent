## 1. 目的与范围

### 1.1 目的

本守则规定 Android Global Agent（AgentLite 形态）**软件交互逻辑**的工程规范：交互循环生命周期、动作体系契约、决策优先级、降级与容错、循环治理、终态语义、安全红线、可观测性与变更管理。目标：

1. **行为可预期**——同一屏幕状态与任务语境收敛到同一动作选择；
2. **过程可验证**——每步动作以屏幕变化复验，终态自证；
3. **风险可控**——模型侧敏感纪律为主防线，引擎守卫为辅助防线，任何时刻用户可停；
4. **演进可治理**——动作词表与守则的变更受版本、评审、测试三重门禁约束；规范要求与当前实现的差距以偏差登记（附录 D）显式管理。

### 1.2 范围

**纳入**：AgentLite 引擎的动作词表（`SCHEMA`）、主循环治理、降级链、敏感守卫、生态策略、终态语义，以及上述各项的设计、评审、实现、测试与变更。

**不纳入**：`agent-client/`（Root 完整版）的虚拟屏沙盒与 Root 守护进程逻辑；`agentd-go/` 实验方案；服务端（`agentlite-server/`）API 契约；HarmonyOS 适配（另见 `docs/HARMONY_*.zh-CN.md`）。

## 3. 总则（交互不变量）

以下不变量是本守则的根约束，任何变更**必须不**破坏：

- **INV-1 原子性**：每轮决策**必须**产出恰好一个 JSON 动作对象；多动作、自由文本、markdown 代码块均**必须不**出现。
- **INV-2 引用即时性**：节点编号每步重新分配；动作**必须**只引用最新节点表编号。
- **INV-3 复验义务**：动作执行后的进展判定**必须**基于屏幕实际变化（感知树 / 截图），而非动作发出与否。
- **INV-4 终态自证**：终态**必须**携带摘要（done）或归因（fail）；以 done 冒充失败**必须不**发生。
- **INV-5 用户主权**：任务运行中用户**必须**随时可停；敏感场景**必须**经 `ask` 确认或触发接管。
- **INV-6 锁屏红线**：引擎与模型**必须不**尝试绕过锁屏；正确行为是 `wake` 后仍锁屏则请用户解锁。
- **INV-7 降级有序**：通道失败后**必须**沿既定降级链切换，**必须不**原样重试失败通道。

## 4. 交互循环生命周期规范

### 4.1 阶段定义

```text
[可选 P0 规划] → P1 感知 → P2 决策 → P3 执行 → P4 复验 → (回到 P1) → P5 终态
```

| 阶段 | 职责 | 规范要求 |
|---|---|---|
| P0 规划 | 独立规划模型把口语任务整理为：目标、步骤、完成判据、风险提示 | **可以**由用户关闭；规划失败**必须**静默降级为直接执行，**必须不**阻断任务 |
| P1 感知 | 采集节点表（上限 25 节点、clickable 前置重排）+ 截图 + 屏幕形态 | 感知输入**必须**同时注入节点语义与视觉两通道；节点为空且屏幕全黑**必须**解释为加载中；连续 ≥2 步空节点自动附带截图（纯视觉降级） |
| P2 决策 | 先过敏感守卫（现状见 §10.1 与 DEV-1），再按 §6 优先级选择动作 | **必须**先做环境态判定（§4.2）再选层 |
| P3 执行 | 引擎按 §7 降级链执行 | 执行失败**必须**以错误信息回报进上下文（截断 300 字符），**必须不**静默吞掉 |
| P4 复验 | `waitForChange`：前置 60ms + 80ms 轮询，上限 600ms | `wait` 动作本身除外；复验结果驱动 §8 循环治理 |
| P5 终态 | done / fail / 用户停止 | 见 §9；主循环 finally 块**必须**归还借用的输入法（`restoreIme`） |

**步数计量**：`ask` 消耗一个决策步（5 分钟超时，等待期用户可停止）；敏感接管不消耗（`step--`）；`maxSteps` 用户可配、默认 50。

### 4.2 环境态判定（决策第 0 层）

进入动作选择前**必须**按序判定：锁屏/息屏 → 应用加载中 → 突发界面（开屏/插屏广告 → 系统权限弹窗 → 系统对话框 → 运营弹窗 → 登录/注册墙 → 异常跳转 → 新手引导/分步指引）→ 敏感场景（§10）。各环境态的强制动作与禁止动作见配套 Skill §3 与 `SCHEMA` 守则 4（突发界面处置的单一事实源，由 `tests/popup_ad_guard.py` 门禁守护）；其中「加载中禁止 `key 3` / `key 4` / `edge_back`」为**必须**级约束（防止把刚启动的应用退掉），「突发界面处置后未复验不得恢复原任务动作」「同一弹窗两轮处置无效必须换策略」同为**必须**级约束。

### 4.3 上下文治理

对话上下文**必须**裁剪为：system + 任务 + 最近 8 条。裁剪策略变更**应**经性能与成功率双重评估。

### 4.4 操作记忆库与复现路径（回放）

记忆库（`FlowMemory` + `FlowPlan`）把「同一句话成功走过一次」的路径变成**零模型往返**的直接复现。
它插在决策第 0 层**之前**：命中即回放，回放不成立才回到常规循环。

1. **R-1 加速器边界（必须）**：记忆库**必须不**成为新的故障点。复现任何一步走不通，都**必须**落回
   模型规划路径继续任务；禁止因记忆库异常而终止任务，禁止把复现失败直接当作任务失败。
2. **R-2 三态终局（必须）**：复现结局**必须**区分三态，不得退化为「成/败」二元——
   - `REPLAY_OK`：整条走通 → `markOk`（刷新成功计数）；
   - `REPLAY_STALE`：**路径失效**（界面改版、目标消失、连续无变化）→ `markFail`（记录贬值）；
   - `REPLAY_INTERRUPTED`：**环境打断**（突发弹窗两轮处置无效、敏感场景接管、无障碍服务断开）
     → **不得**记失败。此前无差别 `markFail` 会让两次运营弹窗误退役一条好记录。
3. **R-3 一次性突发界面步骤不得入库（必须）**：采集侧对每一步做弹窗关闭步判定
   （`PopupGuard.isDismissAnchor`：可见文本锚点 + 关闭字形 + 安全位置 + **任务语义约束**），
   命中即**跳过入库**并在日志留痕（「操作记忆跳过一次性突发界面步骤」）。广告/运营弹窗是
   **环境噪音**，把它记进路径会让下次复现去点一个已经不存在的按钮。判定**必须**受任务语义
   约束：任务本身就是「取消订单」时，`取消` **不得**被当噪音跳过。
4. **R-4 指纹与命中（应）**：记录**应**携带转译骨架指纹（`fp_skel` = 意图 + 步骤骨架），
   使「同款不同参」的任务（点奶茶 → 点咖啡）也能命中；同一句话的精确命中优先于骨架命中。
   骨架命中注入的提示**仅作参考**，屏幕实况与之冲突时以实况为准（§4.2 同源原则）。
5. **R-5 跨设备与直达流程整条作废（必须）**：路径中出现 `remote`（跨设备）或 `open_api` 直达
   等与屏幕实况无关的动作时，整条流程**不得**作为可复现记录（见 §5.2 动作契约）。
6. **R-6 回放侧弹窗处置（必须）**：回放中遇到突发界面**必须**先按 §4.2 处置再续跑；两轮处置
   无效即判 `REPLAY_INTERRUPTED` 并回退模型，**不得**无限重试或把弹窗误判为路径失效。

## 5. 动作体系规范

### 5.1 分层总表

| 层 | 定位 | 动作（以 `SCHEMA` 注册为准） | 稳定性预期 |
|---|---|---|---|
| L1 直达 | API/DeepLink/Intent | `open_api` `open_url` `app` `list_apps` `setting` `wifi` `bluetooth` `brightness` `volume` `statusbar` `wake` `remote` | 高（不依赖 UI 布局） |
| L2 节点 | 结构化语义 | `tap(index)` `longpress(index)` `text` `wait` | 高（语义对齐） |
| L3 视觉 | 坐标估计 | `tap(px/py \| x/y)` `swipe` `scroll` `key` `edge_back` | 中（依赖截图估计） |
| L4 控制 | 终态与用户 | `ask` `done` `fail` | — |

注：`exec()` 内存在 `back` / `home` 分支（约 L1039–L1042）但未注册进 `SCHEMA`，模型不可达，属词表注册不完备（DEV-7）；其返回值被忽略，与 INV-3 相悖，修复时**必须**补注册或删除，并处理失败回报。

### 5.2 动作契约（元规则）

每个动作的完整字段契约以 `AgentEngine.SCHEMA` 常量为单一事实源，本守则**必须不**复制字段清单全文（防漂移），仅固化元规则：

1. **M-1** 新动作**必须**定义：`action` 值、必填字段、默认值、失败语义、所属层级。
2. **M-2** 坐标类动作**必须**同时支持绝对像素与 `p*` 比例坐标（0~1）两种寻址，比例坐标为跨设备首选。
3. **M-3** `text` **必须**支持中文/Unicode；执行前**必须**已聚焦输入框。
4. **M-4** `wait` 的 `ms` **必须** ∈ [200, 8000]，缺省 1500。
5. **M-5** `scroll.direction=down` 语义固定为「内容向下翻（手指上滑）」，**必须不**另立解释。
6. **M-6** `app` 动作**必须**保留三段解析（常用名表 → 已装模糊解析 → `list_apps` 提示）。生态三档（AUTO/LOGIN_ONLY/BLOCKED）现状：`exec()` 取档仅用于展示名，无分级分支、默认全 AUTO（DEV-3）；规范要求：三档**应**在启动前生效——LOGIN_ONLY 拦截 AI 代操作、BLOCKED 降级纯视觉——接线前以偏差登记追踪。
7. **M-7** `open_api` 未匹配协议时**必须**回退通用意图（`geo:` 搜索 / `ACTION_WEB_SEARCH`），执行异常时**必须**降级 `app` 直启。
8. **M-8** `fail.reason` **必须**非空；`done.summary` **必须**非空。
9. **M-9** 词表注册完备性：`exec()` 分支与 `SCHEMA` 词条**必须**一一对应；新增 `exec` 分支而未注册词表（或反之）视为未完成变更。

### 5.3 动作注册与注销

- 新增动作：**必须**同步更新 `SCHEMA`、配套 Skill §4、本守则 §5.1，并通过 §12 门禁；
- 废弃动作：**应**保留至少一个次要版本周期并在 `SCHEMA` 标注弃用说明，**必须**在 CHANGELOG `Deprecated` 记录；
- 任何字段语义变更（含默认值）按破坏性变更处理（§13.2）。

## 6. 决策优先级规范

1. **D-1 API 优先**：凡搜索商品/地点导航/视频/歌曲/拨号等存在 L1 通道的需求，**必须**优先 L1，规避启动页广告与多级点击。
2. **D-2 节点优先于坐标**：目标存在于节点表时**必须**用 `index`。
3. **D-3 隐式意图推理**：决策**应**完成隐式需求→意图→关键参数的抽取（例：「查去深圳北站怎么走」→ navigate + 深圳北站），**不应**丢弃修饰性过滤条件。
4. **D-4 完成即止**：「打开类」任务见目标主界面即 done；「打开并做一个动作」类完成该动作即 done；**不应**继续探索。
5. **D-5 应用内跳转不是离开**：页面跳转**必须不**触发返回/重启；判据是任务进展而非所在页面。
6. **D-6 授权不重复确认**：任务中已明确授权的步骤直接执行；仅支付/转账/发消息/删数据前**必须**再 `ask`。
7. **D-7 禁触区修正服从**：收到「坐标被修正 Npx（>40）」提示后，**必须**基于修正后位置重新决策。

## 7. 降级与容错规范

| 场景 | 降级链（依序） | 规范 |
|---|---|---|
| 点击 | 节点 `ACTION_CLICK` → 手势坐标 →（Root 可用）`input tap` | 每级失败**必须**进入下一级 |
| 文字输入 | `ACTION_SET_TEXT` → 缝合键盘 IME → 剪贴板+长按粘贴引导 | 三级全败**必须**抛出含权限指引的错误 |
| 返回上级 | `key 4` → 节点表返回节点 → `edge_back` | 一条无反应**必须**立刻换下一条 |
| 启动应用 | 常用名表 → 已装模糊解析 → `list_apps` | **必须不**盲猜包名 |
| DeepLink | `open_api` 协议 → `app` 包名直启 | 异常**必须**记录日志后降级 |

**单步失败与任务失败的边界**：单步执行异常进入重试循环（错误回报上下文，模型换法）；任务级失败（`TaskFailException`、授权等待期停止、步数耗尽、看门狗）**必须**直达终态，不走重试。

## 8. 循环治理规范

| 机制 | 参数（现行实现） | 规范 |
|---|---|---|
| 重复动作检测 | 动作键 = `动作\|index\|x÷30,y÷30`；连续 ≥2 次触发警告 | 阈值调整**应**附 A/B 数据 |
| 无进展看门狗 | 普通节点语义指纹连续 6 步不变；纯视觉/状态栏污染场景用动作后新截图的视觉摘要 | 终止理由**必须**进入失败卡片与历史；纯视觉截图失败时不得依据旧节点或旧截图误杀，继续交给模型复验 |
| 震荡看门狗 | 最近 **6 步**内屏幕状态 ≤2 种**且**动作 ≤2 种（A↔B 来回横跳、屏幕无进展） | 立即 fail，归因「页面在两状态间反复切换」|
| 步数上限 | `maxSteps` 默认 50；`ask` 计步、接管不计步 | 超限话术**必须**引导「缩小任务范围后重试」 |
| 自适应等待 | 前置 60ms + 80ms 轮询 / 上限 600ms | **不应**在机制外叠加固定长 sleep |
| 应用启动等待 | 1.0s | 变更需带实测启动分布数据 |
| 上下文窗口 | system + 任务 + 最近 8 条 | — |

**模型对抗禁止**：收到无进展警告后仍第三次执行同键动作，同时违反 INV-3（复验义务）与 INV-7（降级有序），**必须**在评测集（§12.2）中记为缺陷。

**守卫失效窗口披露**（对应 DEV-6）：敏感守卫在 ① 节点为空（纯视觉/被屏蔽应用）与 ② 接管交还后连续 2 个决策步（`guardSkipStep = step+1` 且 `step--` 的防重复触发取舍）两个窗口不扫描。窗口②内模型侧敏感确认义务不豁免（Skill §7.2 接管窗口纪律）；窗口①由模型纯视觉敏感自判补偿，中期**应**引入截图侧守卫（附录 D）。

## 9. 终态与归因规范

1. **T-1** 四种合法终态：done、fail、用户停止、**不确定**；用户停止**必须**静默终态（授权等待期停止不弹失败卡片）。「不确定」是 done 在**证据不足**时的降级态：模型自报完成但既无前台到达证据、也无前台变化（`judgeDone` = `UNPROVEN`），此时**必须不**记为完成——它是「结果待人工确认」，不是失败，也不得伪装成成功。
2. **T-2** 归因**必须**落入附录 B 七类之一（应用受限 / 超时 / 目标不存在 / 权限不足 / 无障碍服务断开 / 模型调用失败 / 内部异常）；模型侧 `fail.reason` **应**归因到前四类，后三类为引擎自产归因（引擎直接终态）。
3. **T-3** 完成终态（`PROVEN` / `WEAK`）**必须**展示绿色完成卡片并写入本地历史（`history("完成", summary)`）。
4. **T-3a** 完成语义位**必须**独占：绿色完成卡与胶囊「完成:」前缀只允许出现在 T-3 路径；「不确定」终态**必须**用独立卡片（琥珀色）且文案**必须不**含「完成」字样，避免把「没证据」读成「已完成」。
5. **T-3b** 无证据终态**必须不**写操作记忆库（`recordable = false`）：失败或不确定的路径不可信，入库等于把不可靠流程复制给下一次任务。
6. **T-4** 归因文案由模型给出、引擎统一加工，**必须不**向用户暴露堆栈或内部字段名。
7. **T-5** `ask` 阻塞等待 5 分钟超时；等待期间用户可停止任务。

## 10. 安全与合规红线

### 10.1 敏感场景守卫（现状 + 规范）

`SensitiveGuard` 词表四组、`scan()` 按组序（支付 > 验证 > 协议 > 权限）精确子串匹配节点文本，命中即弹接管卡片（不消耗决策步）。

**现状（as-built）**：`scan()` 仅接线前两组（DEV-1）：

| 组 | 词条（现行词表） | 接线状态 | 用户侧呈现 |
|---|---|---|---|
| 支付 | 支付密码、请输入支付密码、输入支付密码、确认付款、立即支付、交易密码、银行卡密码、指纹支付、输入密码付款（9 词条） | ✅ 已接线 | 「检测到支付付款界面——支付需由你本人确认」 |
| 验证 | 短信验证码、输入验证码、验证码、人脸识别、人脸验证、刷脸、指纹验证、请验证指纹、输入密码、登录密码、图形验证（11 词条） | ✅ 已接线 | 「检测到身份验证界面——密码/验证码需由你本人输入」 |
| 协议 | 同意并继续、已阅读并同意、阅读并同意、同意协议、服务协议、隐私政策、用户协议（7 词条） | ❌ 声明未接线 | — |
| 权限 | 仅在使用期间允许、仅本次允许、使用期间允许、始终允许使用（4 词条） | ❌ 声明未接线 | — |

**规范条款**：
- **S-1** 词表与分组变更（增/删/改）**必须**经过安全评审，**必须**在 CHANGELOG 记录。
- **S-2 双防线不对等披露**：模型侧纪律（`SCHEMA`：支付扣费/转账/发送敏感信息前**必须** `ask`；密码/验证码绝不代填）是**主防线且全覆盖**；引擎守卫是**部分覆盖的辅助防线**（仅 2/4 组、精确词条、非空节点、存在 §8 披露的失效窗口）。「转账」「红包」「免密」等词不在引擎词表内，拦截完全依赖模型侧。**必须不**以「引擎会拦」为由削弱模型侧纪律，也**必须不**以「模型会问」为由拒绝补齐引擎守卫（词表四组**应**全部接线，见 DEV-1/DEV-2）。
- **S-2a 覆盖差距**：支付类词条**应**扩展覆盖转账、汇款、红包、免密、连续扣费等资金场景（DEV-2），扩展前该缺口由模型侧红线显式承担（Skill §7.2）。

### 10.2 授权与生态策略（现状 + 规范）

**现状（as-built）**：
- **事前授权**：授权存储与管理入口存在（设置页授权管理 UI）；但动作执行前的授权检查 `requestAuth()` 无调用点，动作级「操作类型 × 应用」拦截未接线（DEV-4）。
- **生态三档**：`EcoPolicy` 定义 AUTO / LOGIN_ONLY / BLOCKED 三档；`exec()` app 分支取档仅用于展示名，无分级分支，注释明示「彻底关闭任何阻断性安全拦截」；`visionForced` 永为 false，纯视觉降级路径为死代码；默认策略全 AUTO（DEV-3）。
- **事中控制**：任务运行中可停止（`stopRequested` 各阻塞点响应）或补充要求（补充要求进入后续决策上下文）——**已实现**。
- **事后追溯**：任务结果写入本地历史（`TaskHistory`，终态级）——**已实现**。

**规范条款**：
- **S-3** 事前授权模型接线后，「操作类型 × 应用」**必须**支持单次允许 / 始终允许 / 拒绝三选项，未授权应用的动作**必须**被拦截并触发授权卡片；接线前该层防护缺位状态**必须**保留在偏差登记（DEV-4），且**必须不**对外宣传「事前授权拦截已生效」。
- **S-3a** 生态三档接线后：LOGIN_ONLY **必须**拦截 AI 代操作（用户可手动）；BLOCKED **必须**降级纯视觉或拒绝启动；默认档位变更**必须**显式记录。接线前默认全 AUTO 且无分支的现状**必须**保留在偏差登记（DEV-3）。

### 10.3 隐私

**S-4** API Key 只存本机；任务历史与显式记忆**必须**保留在设备本地，同步功能**必须**默认关闭且显式 opt-in。

## 13. 变更管理

### 13.1 角色与职责

| 角色 | 职责 |
|---|---|
| 提交者 | 提出变更、同步三处 artifact、跑 §12 门禁 |

### 13.2 变更分级

| 级别 | 定义 | 流程 |
|---|---|---|
| 破坏性 | 删除动作、字段语义变更、默认值变更、词表删词 | 0.x 阶段升 minor（SemVer 第 4 条），1.0 起升 major + 全量 §12 门禁 + 安全评审（涉及时） |

| 文档性 | 仅改 Skill/守则 | 版本 patch + §12.4 一致性核对 |

### 13.3 版本与记录
