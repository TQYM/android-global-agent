> ⚠️ **实现时必须写死的坑**：**认证失败也可能返回 HTTP 200**。

## 4. 设计缺口（我从 `PURCHASE_REDIRECT_DESIGN` 里读出的 4 处，开工前建议先定）

1. **返回检测没设计**：流程图写「返回 App，自动检测返回」，但没定机制（`onResume` + 时间窗？`intent://` 回跳？）。
   官方购买页大概率不接受自定义 scheme 回跳；若只能靠 `onResume` 猜，
   会出现「用户切出去看了眼微信再回来」被误判为「已付款」的假阳性，下一步就直接去调 `CreateApiKey` 了。
2. **回滚语义模糊**：§6 说失败必须可回滚，但没说回滚哪一层。
   官方那边钱已花，物理上退不回；能回滚的只有本地状态。
   → 建议写成「本地不进中间态 + 明确引导到『更改 API』手填」，别让人误读成能撤销支付。
3. **AK 的录入路径缺失**：§7 要 RAM 子账号 AK，但 §4 清单里没有任何界面接这个 AK（`AkStore` 只写了「存储」）。
   缺「首次使用录入 AK + 当场校验权限」的流程，否则 `CreateApiKey` 无凭据可签。
4. **`use_gateway` 判定口径未定**：§4 写「置 false 或按账号来源判断」——二选一没选。
   全局置 false 会让老用户也掉出网关模式。

另：`agent-unified/client/src/com/dsh/agentlite/` 下有 `PurchaseActivity` / `SettingsActivity` / `LlmClient` 的**平行副本**，
设计文档只提 `agent-lite/`。开工前先定谁是真身、另一份是否同步，否则会改一半。
